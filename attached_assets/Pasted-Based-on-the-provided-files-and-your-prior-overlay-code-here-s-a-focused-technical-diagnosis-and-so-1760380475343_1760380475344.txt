## Diagnosing Your Problem

### **1. Multiple H2H overlays**

- In `LivePresentation-5.tsx` and `VideoCompositor.tsx`, overlays are kept in an array (e.g., `overlays`) and rendered via a component lookup.
- No deduplication appears for overlays of type `'h2h-card'` or with the same pair of teams (`homeTeamId`, `awayTeamId`).
- The UI or overlay manager might let users add the same overlay multiple times, creating multiple cards for the same matchup.
- Each overlay gets rendered as its own component (`H2HMatchCardOverlay`). Thus, unless you filter overlays “by unique matchup,” you will always have stacking/copies.

**Solution:**  
- In the overlays creation logic, especially when adding or toggling overlays, add a check to the handler so an H2H overlay with the same two teams (both orders, as H2H is symmetric in display) does not get added twice.

### **2. Dotted Line Overlay Artifact**

- The dotted line is rendered using conditional classes on component wrapping DOM elements, usually for edit selection/highlighting or drag.
- Example (from your code):  
  In `LivePresentation-5.tsx`:  
  ```jsx
  <div
    className={
      isEditing
        ? 'absolute rounded pointer-events-none bg-primary/30 border-2 border-primary z-10 bg-white/10 border border-white/30'
        : ''  
    }
  />
  ```
- The border/highlight is tied to the overlay’s editing position (`isEditing` or similar state).
- If the overlay can be dragged outside the black canvas, the highlight and card can move out of bounds, because constraints are only enforced via `constrainOverlayPosition` on overlay reposition.

**Solution:**  
- Make sure the drag/resize handlers always clamp overlay x/y so the full card never leaves the bounds (canvas/broadcast region).
- Only display the highlight/dotted border in edit mode—not in live output.

### **3. Border/Artifacts Extending Outside**

- Positioning is based on absolute `top` and `left` coordinates (in px), which can place the overlay and its borders outside the black screen.
- The constrain logic exists, but **ensure it runs on EVERY position update** (drag, resize, manual coordinate entry).
